# mind-the-chl-gap: Indian Ocean zarr EDA

EDA of `IO.zarr`, the daily 0.25° Indian Ocean dataset from
[geo-smart/mind-the-chl-gap](https://github.com/geo-smart/mind-the-chl-gap)
([docs](https://geo-smart.github.io/mind-the-chl-gap/notebooks/IO_Zarr.html)).
It spans 32°N to 12°S and 42–102°E, 1979–2022, with CHL (GlobColour L3 and gap-free L4), ERA5 wind and temperature, OSCAR currents, CMEMS sea level, and GLORYS mixed-layer depth and salinity.

## Setup in a new SageMaker session

```bash
cd ~/shared/ecology/mind_the_chl_gap
pip install xarray dask zarr gcsfs "numpy==1.26.4"   # keep numpy pinned: newer numpy breaks sagemaker-studio
python fetch_data.py      # ~24.7 GB -> ~/mind_the_chl_gap/data/IO.zarr, ~2.5 min
python io_summaries.py    # optional, ~8 min -> ~/mind_the_chl_gap/data/summaries.zarr
```

Then open `IO_EDA.ipynb`. If the summaries file is missing, the notebook builds it on first run.

Keep the data on local disk (`~/`), not in `~/shared` (s3fs). A zarr store is thousands of small files, which s3fs handles slowly.

## Data source

| | |
|---|---|
| Bucket (public, anonymous) | `gs://nmfs_odp_nwfsc/CB/mind_the_chl_gap/IO.zarr` |
| Size | 24.7 GB on disk, 3,997 files; **66 GB uncompressed** |
| Layout | 27 variables × (time 16071, lat 177, lon 241); chunks of 100 days × full map |

To read it straight from the bucket without downloading (slower, but fine for small slices):

```python
import xarray as xr
ds = xr.open_zarr("gs://nmfs_odp_nwfsc/CB/mind_the_chl_gap/IO.zarr",
                  storage_options={"token": "anon"}, consolidated=True)
```

The same bucket folder also holds project outputs: `U-Net_with_CHL_pred.zarr`, `U-Net_without_CHL_pred.zarr`, `2015_3_ArabSea*.zarr` and the `cnn_*` / `unet_tutorial` folders. `IO_rechunked.zarr` is a 6-variable subset from 1997 onward with small (1, 40, 56) chunks, so it's not a full copy.

How the dataset was built is documented at https://safs-varanasi-internship.github.io/indian-ocean-zarr/. The build code is not in the project repo.

## CNN gap-filling

```bash
pip install torch            # already present on the SageMaker image
python -m chl_cnn.train --run baseline_sst_so                              # sst + so inputs, loss on observed pixels
python -m chl_cnn.train --run chl_in_fakeclouds --chl-input --fake-clouds  # + CHL input, loss on fake-cloud pixels
python -m chl_cnn.train --run baseline_asis --target all_zero              # the published baseline (NaN -> 0, loss everywhere)
# full period (Sept 1997 - Dec 2020; `so` is missing after 2020), year-interleaved split
python -m chl_cnn.train --run full_alldays_fakeclouds --years 1997-09-01 2020-12-31 --split years --chl-input --fake-clouds --target hidden
python -m chl_cnn.train --run full_clear_fakeclouds   --years 1997-09-01 2020-12-31 --split years --chl-input --fake-clouds --target observed --clear-frac 0.6
```

The full-period subset (sst, so, CHL L3; ~2.8 GB) is cached to `~/mind_the_chl_gap/data/cnn_subset_1997_2020_sst-so.npz`.
Use `--split years` there: CHL coverage rises from ~13% (1997) to ~53% (2020) of ocean pixels, so a chronological
split leaves no clear day for training. Training needs ~9 GB RAM free; close idle notebook kernels first.

### Performance runs (`train2.py`)

```bash
python -m chl_cnn.store                                   # once: ~/mind_the_chl_gap/data/cnn_store_1997_2020/ (float16 per variable, ~5 GB)
ALL="sst so air_temp u_wind v_wind sla mlotst u_curr v_curr"
python -m chl_cnn.train2 --run perf_dilated_allfeat --model dilated --features $ALL --clim --coords --residual --context 2
python -m chl_cnn.train2 --run perf_unet32_l1 --model unet --width 32 --features $ALL --clim --coords --residual --context 2
```

Loss on fake-cloud-hidden pixels only (real clouds have no truth and never count; `--vis-weight` adds visible pixels).
`--context K` adds CHL of days t±K; the donor's cloud sequence is applied to those days too, otherwise hidden pixels
leak through the neighbours (`--context-clouds none` reproduces the leak). Options: `--loss l1|huber|mse`, `--clim`
(day-of-year climatology channel), `--coords`, `--residual`. ~90 s per epoch on a T4, ~40 s on an A10G, for the dilated CNN.
`python -m chl_cnn.watch --cat pinn/cnn,pinn/unet --every 60 --out models/progress_pinn.png` redraws a progress figure for the chosen run categories (val MAE per epoch; physics residual for the PINN runs); `notebooks/progress.ipynb` is the interactive version.

Setup follows the baseline: 2020 only, 32°N–5°S / 45–90°E (149 × 181), ln(CHL L3) target, 70/20/10 chronological split,
3-layer CNN (64, 32, 1 filters), MAE loss, Adam, batch 8, early stopping on val. The subset is cached once to
`~/mind_the_chl_gap/data/cnn_subset_2020_2020.npz` (~130 MB). Val/test days get fixed fake clouds (cloud pattern of a
donor day, seeded) so every run is scored on the same hidden pixels. Then open `notebooks/cnn_results.ipynb`.

## Higher-resolution CHL for a region only

Both main 4 km / 1 km sources can be sliced to a lat/lon box server-side, so there is no need to download global files.

**ESA OC-CCI (PML THREDDS, no registration).** `https://rsg.pml.ac.uk/thredds/catalog-cci.html` lists whole-record *aggregations*; open them over OPeNDAP and slice:

| aggregation | resolution | period | Indian Ocean box (32°N-5°S, 45-90°E) | notes |
|---|---|---|---|---|
| `CCI_ALL-v6.0-DAILY` | 4 km (1/24°) | 1997-09 → 2026-06 | 888 × 1080 px, 3.8 MB/day float32, ~0.6 s/day | v6, L3 only (gappy), `chlor_a` in mg m⁻³ linear |
| `CCI_ALL-v5.0-1km-DAILY` | 1 km (1/96°) | 1997-09 → 2021-04 | 3552 × 4320 px, 61 MB/day, ~3.4 s/day | v5; Black Sea box 768 × 1488 px, 5 MB/day, ~1.4 s/day; Med box 1536 × 4080 px, 25 MB/day, ~1.6 s/day |

`fetch_occci.py` pulls a box in time blocks with retries into `~/mind_the_chl_gap/data/occci/<name>.zarr` (resumable), e.g.
`python fetch_occci.py --name blk_1km --dataset CCI_ALL-v5.0-1km-DAILY --box 48 40 26.5 42 --start 2016-01-01 --end 2021-04-30 --vars chlor_a total_nobs`.
Compressed on disk ~0.6 MB per day per variable for the Black Sea box. The full 4 km Indian Ocean record (~9,100 days) takes ~1.5 h.
Early days (Sept 1997) are empty; SeaWiFS data start mid-September 1997. OC-CCI has no daily gap-free L4.

**Copernicus GlobColour / regional 1 km (free registration).** `pip install copernicusmarine`, then `copernicusmarine login` once, and subset by box and dates
(output netcdf or zarr; `--dry-run` reports the size first):

```bash
copernicusmarine subset -i cmems_obs-oc_glo_bgc-plankton_my_l3-multi-4km_P1D -v CHL -v flags \
    -x 45 -X 90 -y -5 -Y 32 -t 1997-09-01 -T 2022-12-31 --file-format zarr -o ~/mind_the_chl_gap/data/globcolour -f io_4km_l3.zarr
copernicusmarine subset -i cmems_obs-oc_glo_bgc-plankton_my_l4-gapfree-multi-4km_P1D -v CHL -v CHL_uncertainty -v flags \
    -x 45 -X 90 -y -5 -Y 32 -t 1997-09-01 -T 2022-12-31 --file-format zarr -o ~/mind_the_chl_gap/data/globcolour -f io_4km_l4.zarr
# Black Sea 1 km: cmems_obs-oc_blk_bgc-plankton_my_l3-multi-1km_P1D / ..._l4-gapfree-multi-1km_P1D   (box -x 26.5 -X 42 -y 40 -Y 48)
# Mediterranean 1 km: cmems_obs-oc_med_bgc-plankton_my_l3-multi-1km_P1D / ..._l4-gapfree-multi-1km_P1D (box -x -6 -X 36.5 -y 30 -Y 46)
```

`fetch_cmems.py` wraps this for the Black Sea and Mediterranean: `download` pulls CHL L3 (CHL, QI_CHL) and gap-free L4 at 1 km plus the regional
physics reanalysis surface layer (thetao, so, uo, vo, mlotst, zos, tauuo, tauvo; 2.5 km Black Sea, 4.2 km Med) as one NetCDF per dataset and year;
`arrange` block-averages CHL (geometric mean, valid count kept) by `--coarsen` and interpolates the physics onto that grid into one zarr per basin
(`~/mind_the_chl_gap/data/cmems/<basin>_<N>km.zarr`, same layout idea as IO.zarr). `./fetch_cmems_all.sh blk 1998 2024 2` does both year by year
from tmux and deletes the raw files as it goes. One Black Sea month at 2 km: 135 MB raw, 90 MB arranged, ~1 min; a full year ~1.1 GB arranged.
The reanalysis domains are smaller than the CHL boxes (no Sea of Azov / Marmara in the Black Sea physics), so ~14 % of CHL ocean pixels have no
physics there (NaN → 0 in training, as for the GLORYS gaps in IO.zarr).

The L4 `flags` variable marks interpolated pixels, which gives a hidden-pixel protocol with the same L3 truth as here. Product details, matching
physical forcing (OSTIA 0.05° SST, MUR 0.01°, GlobCurrent, GLORYS 1/12°, regional 2.5-4 km reanalyses) and sizes: `notebooks/high_res_datasets_survey.md`.

## Gotchas

- Open with `xr.open_zarr(path)`, which uses dask by default. **`chunks=None` turns dask off**: the first operation then loads the full variable (2.7 GB each) and can crash the kernel. The machine has 15 GB RAM.
- The widget cells need a live front end (Jupyter or VS Code). Headless `nbconvert --execute` hangs on them.
- Data issues (details in the notebook):
  - ERA5 is missing whole months in 1979–1992 and 2021–22.
  - `mlotst` for 1979–1992 is an exact copy of `u_wind` (a NaN fill in the build failed on a dask array). Use it only for 1993–2020.
  - The land mask is 0 = ocean, 2 = land; 43 lake pixels are not flagged as land.
